# Junior Soccer Jersey Form

## Run

Requires Node.js 22+ and a Firebase project with Firestore enabled.

1. Run `npm install`.
2. Copy `.env.example` to `.env` and set `GOOGLE_APPLICATION_CREDENTIALS` to a service-account file outside any public directory.
3. Run `npm start` and open http://localhost:8001/ (student form) or http://localhost:8001/admin (dashboard).

The server only serves the form, the admin page, and two approved images. Credentials and student details are never exposed by static routes. Keep `.env` and service-account keys out of version control. Disable direct client access to the `juniorSoccerJerseys` Firestore collection; the server uses Admin SDK credentials.

## Number reservations

Numbers 1–99 are global to this form. Selecting a dropdown option does **not** reserve it; a successful submission does. Each number is a Firestore document ID in `juniorSoccerJerseys`. A transaction checks and creates the document atomically, saving student details with the reservation. Concurrent submissions for the same number receive HTTP 409 except for an identical retry with the same submission ID.

The form refreshes availability every 15 seconds and when the tab becomes active. Taken numbers remain visible but disabled. Final availability is always checked on the server. Reservations remain after restarting the server. To release a number, remove the submission from the admin dashboard.

No student names or other personal information are returned by the availability API. This form is public and unauthenticated; possession of its URL allows submissions. Add authentication or invite validation before using it beyond a trusted school group.

## Student flow

The form has three steps: **Fill in details → Review → Submitted**. Nothing is saved until the student selects **Confirm and submit** on the review page. If the number is taken in the meantime, the student is returned to the form with the number field highlighted.

Class (4, 5, or 6) is required. Number availability updates automatically; there is no manual refresh button or number hint. The review page has no per-field Edit buttons; use **Back to edit** below the details to make corrections before confirming.

## Admin dashboard

Open `/admin`. All admins have the same permissions:

- Summary cards, submissions-per-day chart, size totals for ordering, class breakdown, recent submissions, and a 1–99 number board.
- Searchable, sortable student table.
- **Edit** corrects any detail, including moving a student to a free number (checked in a transaction). Edits record `updatedAt` and `updatedBy`.
- **Remove** deletes a submission and releases its number.
- **Download report** offers two formats:
  - **PDF**: opens a branded, printable report (summary, order totals by size, class breakdown, registration table and a back-of-jersey preview for every student). Choose *Save as PDF* in the print dialog.
  - **Excel (.xlsx)**: a formatted workbook with *Summary*, *Registrations* (filterable, frozen header) and *Number Board* sheets, generated by the server at `/api/admin/report.xlsx` (sign-in required).
- **Export CSV** downloads raw data for other tools.
- Jersey **#0** is reserved for an admin test record: students cannot choose it, and it is not counted in the totals.

Admin accounts are stored in the Firestore `adminUsers` collection with salted scrypt password hashes only. To add an account or reset a password:

```bash
npm run create-admin -- someone@binus.edu "Full Name" "Position"
```

You will be prompted for the password; alternatively set `ADMIN_PASSWORD` for that one command. Running the command again for the same email replaces the password.

Sessions last 12 hours and use an HttpOnly, SameSite=Strict cookie; only a SHA-256 hash of the session token is stored in `adminSessions`. Five failed sign-ins lock that email for 15 minutes from the same address. Changes require a same-origin request. Set `COOKIE_SECURE=true` (or `NODE_ENV=production`) when served over HTTPS.

## Email notifications

When `SMTP_HOST` is set, each new submission emails `NOTIFY_EMAIL` (default recipient: Mr. Ivan). Without SMTP settings, notifications are disabled and the dashboard shows a notice. Email failures are logged and never block a submission. For Google Workspace, use `smtp.gmail.com`, port 465 with `SMTP_SECURE=true`, and an app password.

## Deploy to Vercel

1. Import the GitHub repository in Vercel (framework preset: Other, no build command).
2. Add these environment variables under Project Settings > Environment Variables:
   - `FIREBASE_SERVICE_ACCOUNT`: the service account key, base64 encoded:
     `base64 -w0 your-firebase-adminsdk-key.json`
   - `PUBLIC_URL`: the deployed address, e.g. `https://soccer-jersey.vercel.app`
   - Optional email: `NOTIFY_EMAIL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`
3. Deploy. All routes go to `api/index.js`, which runs `server.js` as a serverless function.

Notes:
- The key file and `.env` are git-ignored and must never be committed.
- Cookies are marked Secure automatically on Vercel.
- Login throttling is kept in memory, so on Vercel it applies per function instance.
- Admin accounts live in Firestore; create or reset them locally with `npm run create-admin`.

## Tests

- `npm test`: validation, password hashing, and notifier tests without database writes.
- `npm run test:firestore`: real Firestore integration tests, including concurrent submissions and admin edits, number moves, and removals. Uses a unique temporary test collection, then deletes its test documents. Requires Firestore credentials and incurs a small number of reads/writes.
